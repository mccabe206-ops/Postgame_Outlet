# Offensive inventory version 2: verified playing-time identifiers

Declared September 13, 2026, after the user authorized repairing the missing player-ID links and before implementation. This extends future descriptive collection only. The original charter, version 1 inventories, selections, exclusions, prior research and forecasts remain unchanged. There is no model fitting, injury coefficient, replacement-quality value or automatic predictive adoption.

Use the full nflverse player table at `https://github.com/nflverse/nflverse-data/releases/download/players/players.csv`. Preserve actual raw response bytes and their hash, byte count and real capture clock in the normal source archive. Provider modification time is not a substitute for actual capture. The source must have been captured by inventory generation, no more than 24 hours earlier, and before each eligible game's T-60; actual inventory durable saving must also precede T-60.

The current roster remains the authority for membership and team. Match the provider table by exact canonical GSIS ID; an empty or noncanonical GSIS cannot be filled by a display name. Require a unique provider GSIS/PFR ownership relationship, matching nonempty normalized name aliases and birthdate, and no conflict among jointly available ESB, NFL, smart or ESPN identifiers. Validate roster-side PFR ownership too. Do not infer identities from team changes, similar names or draft/position expectations. Provider team labels do not set the current roster team.

Keep an existing unique roster PFR ID only when it has no conflicting available provider identity evidence. Fill a missing PFR only from the qualified provider row. Duplicate, malformed, mismatched or missing records remain explicitly unresolved; derived conflict rows cannot feed the snap join. Raw roster/source bytes are never edited. Save every qualified or unresolved result with the version 2 player, including status and reasons, and retain the exact provider source reference. Name aliases admitted from the verified provider are source evidence, not fuzzy matching.

Version 2 replay must reproduce the whole saved inventory from its exact archived roster, role, availability and identity sources. It may supply a detached qualified roster to the existing same-game/team/opponent/PFR-to-GSIS snap join. It must never use the current player table when replaying an older selection. Version 1 continues its original roster-only PFR semantics and does not gain links retrospectively. Existing exclusions stay excluded; the latest actual eligible pregame capture is still selected and frozen by the established monitor.

The player-ID source refresh is independent of the main predictions and defensive source maintenance. Missing, stale, corrupt or failed identity evidence blocks the new offensive capture and retains earlier evidence without suppressing grading. No fallback to an older, easier identity table after a selected source fails. Future provider updates can improve future inventories but cannot rewrite earlier ones.

Report qualified, missing and conflicting links separately from basic GSIS roster identity, with offensive-line coverage shown explicitly. Missing playing-time rows remain unknown; only an explicit valid zero is zero. A complete ID link is not proof that a player played, was healthy, was a replacement, or affected the score. Numerical forecast adjustment remains null and predictive status remains UNAVAILABLE.

Verification includes real missing-PFR roster rows; conflicting/duplicate GSIS/PFR/name/DOB/auxiliary records; missing canonical identity; source clocks/hash/path/CSV structure; retained raw roster; exact version 1 and 2 replay; same-game/opponent/target-name checks; zero and positive snaps; strict T-60 and durable crossing; preserved selections, results, confidence and forecasts; source failure isolation; and meaningful public coverage labels.

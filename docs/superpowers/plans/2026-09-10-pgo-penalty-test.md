# PGO penalty test and monitoring implementation plan

Goal: execute the one-feature experiment in [the locked charter](../../../research/pgo_penalty_candidate/charter.md), then keep a separately labeled prospective comparison up to date.

Architecture: reuse the frozen postseason feature rows, existing fit/evaluation helpers, existing season state archives and existing scheduled runner. Use Python standard library plus the repository's installed NumPy. Keep primary forecasts and model coefficients unchanged.

- [ ] Candidate: create `research/pgo_penalty_candidate/candidate.py` and `tests/test_pgo_penalty_candidate.py`. Expose `FEATURE = 'prior_penalty_yards_per_game'` and `penalty_history(games, team_rows, initial=None)`, returning `pregame` per game and terminal `states` of team to `[numerator, denominator]`. Games use normalized `home`, `away`, `game_id`, `season`, `week`, `game_type`, `kickoff`; source rows retain their provider identities. Add the feature to copied frozen rows, verify original columns and baseline replay, then use existing symmetric fitting and metric helpers. Run the chartered fit once in a new exclusive attempt directory. Export fixed fit, terminal seed, metrics and paired predictions with a hashed manifest.
- [ ] Monitor: create `pgo_penalty_monitor.py` and focused tests. `refresh_shadow(state, previous, root, checked_at)` returns a separately labeled `penalty_shadow` payload; use verified captured team statistics and current ranking features, preserve issued pairs, exclude locked games from new issuance and grade only verified finals. Export `check_durable_shadow(state, previous, durable)` for the existing durable-write cutoff guard. No refitting or new scheduler.
- [ ] Integrate: call the monitor after primary cutoff restoration, enforce its durable cutoff in `save_state`, and render a plain-language collapsed comparison in the existing season view. Keep failures local to candidate status. Include candidate/monitor tests in the scheduled check and watch relevant files in the existing full-CI workflow.
- [ ] Verify and publish: focused chronological/identity/immutability checks, independent review, full required tests, fixed research result, true-clock prospective issuance, source/package hashes, primary forecast preservation, public bytes and a scheduled monitoring run. Keep the failed screen visible if penalties do not help. Confirm weekly updates still require every game and the necessary statistics.

The user already authorized execution and ongoing checking; proceed without an additional approval gate. A validation failure must be reported and repaired as a new recorded attempt; it cannot be erased by rerunning in place.
